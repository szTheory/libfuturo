# Muhtari installed-session fixture and oracle

The public installed consumer builds an original Atari 7800 A78 diagnostic
from C at test runtime. It uses no commercial ROM, firmware or copied upstream
test bytes. The generator is project-authored under this repository's
Apache-2.0 license; generated bytes are written only below ignored build
output.

## Image and program recipe

The generator emits 16,512 bytes: a 128-byte A78-v1 header followed by one
linear 16-KiB ROM. It declares NTSC, joystick device type 5 on both ports,
and reset/NMI/IRQ vectors to `$C000`; no BIOS is supplied. The remaining ROM
bytes are NOP-filled. The admission recipe was checked against the pinned
Muhtari image parser and public `muhtari_media` contract.

The original 6502 program starts at `$C000`, disables interrupts and decimal
arithmetic, and sets TIA channel 0 to volume `$0F`, waveform `$04`, and divider
`$00`. The input loop begins at `$C00E`. Fire is checked through `INPT4` and
`INPT5`; when both are released, `LDA #mask; BIT $0280; BEQ target` checks
active-low SWCHA direction pins in port-0 then port-1 order. The selected
literal is written to MARIA BACKGRND at `$C091`, and the loop jumps back to
`$C00E`.

Fire combinations select:

| Port 0 fire | Port 1 fire | Raw index value |
|---|---|---:|
| pressed | released | `$11` |
| released | pressed | `$22` |
| released | released | `$33` |
| pressed | pressed | `$44` |

When neither fire button is pressed, the first matching direction selects a
distinct raw index:

| Input | SWCHA active-low mask | Raw index |
|---|---:|---:|
| Port 0 Up | `$10` | `$51` |
| Port 0 Down | `$20` | `$52` |
| Port 0 Left | `$40` | `$53` |
| Port 0 Right | `$80` | `$54` |
| Port 1 Up | `$01` | `$61` |
| Port 1 Down | `$02` | `$62` |
| Port 1 Left | `$04` | `$63` |
| Port 1 Right | `$08` | `$64` |

The priority is port-0 Up, Down, Left, Right, then port-1 Up, Down, Left,
Right. Therefore the mixed libfuturo mask `$2010` (port-0 Up and port-1 Down)
selects `$51`; the test also checks those controls individually, so a swapped
or shifted mapping changes a separately asserted case.

The installed public consumer submits this 15-advance sequence. Masks use the
public libfuturo bit assignments; `$0000` means all controls released.

| Advance | Mask | Expected raw index | Observation |
|---:|---:|---:|---|
| 1 | `$0001` | `$11` | Port-0 Button 1; supplied before the first opcode |
| 2 | `$0100` | `$22` | Port-1 Button 1; `set_input` plus zero-work advance first leaves progress at 1 |
| 3 | `$0000` | `$33` | Both fire buttons released |
| 4 | `$0101` | `$44` | Both fire buttons pressed |
| 5 | `$0010` | `$51` | Port-0 Up |
| 6 | `$0020` | `$52` | Port-0 Down |
| 7 | `$0040` | `$53` | Port-0 Left |
| 8 | `$0080` | `$54` | Port-0 Right |
| 9 | `$1000` | `$61` | Port-1 Up |
| 10 | `$2000` | `$62` | Port-1 Down |
| 11 | `$4000` | `$63` | Port-1 Left |
| 12 | `$8000` | `$64` | Port-1 Right |
| 13 | `$2010` | `$51` | Mixed port-0 Up + port-1 Down; priority selects port-0 Up |
| 14 | `$2010` | `$51` | Same held mask advances another interval and produces another image |
| 15 | `$8000` | `$64` | Later input change to port-1 Right |

## Independent startup image derivation

The startup oracle was authored from the generated instruction bytes and
Muhtari's documented raster timing before comparing it with runtime output.
The no-BIOS NTSC fast handoff begins at line 240, tick 24. Each TIA zero-page
store costs 14 master ticks. Before the first input read the setup uses
82 ticks. For port 0 pressed and port 1 released, the subsequent path is:

| Instruction segment | Ticks |
|---|---:|
| `LDA $000C`; first BMI not taken | 26 |
| `LDA $000D`; second BMI taken, including its branch dummy cycle | 30 |
| `LDA #$11`; `JMP $C091`; `STA $0020` | 36 |
| **Total after handoff** | **174** |

The MARIA BACKGRND write is therefore at raster line 240, tick 198. MARIA
emits pixel `x` at tick `135 + x` on that raster, so pixels 0–63 retain their
initial `$00` and pixels 64–319 carry `$11`. Rows 0–223 have not been scanned
since load and are cleared to `$00`; rows 225–241 use `$11`. This derivation
depends only on the fixture instruction recipe and documented timing, not on
captured pixels. The consumer then compares every expected active pixel and
checks stride padding and bytes after the extent.

The same loop puts `$22` on screen for port-1-only fire and `$33` when both
fire inputs are released. The both-fire path uses `$44`; direction paths use
the table above. Each later steady image contains the selected raw color in
all `320 × 242` active pixels. Runtime output serves only as the comparison
subject. A mismatch remains a failure; an observed value is never copied into
the oracle.

## Audio and progress oracle

The fixture writes `AUDV0=$0F`, `AUDC0=$04` and `AUDF0=$00`. The no-BIOS
handoff begins with the TIA's hidden zero-start logic already advanced on its
absolute 456-tick lattice while volume is zero. The writes occur at relative
master ticks 37, 59 and 81; mode 4 is active before its first B edge at tick
64. With the prior silent pulse state at `$0F`, the first audio-level change
after the mode write occurs at tick 744, followed by alternating 224/232-tick
B-edge intervals. The fixed TIA mix curve maps raw channel level 15 to
`18,360 × 2/3 = 12,240` normalized current units. These facts specify the
source event stream without reading PCM from the core under test.

The independently calculated PCM stream applies the documented 16-tap,
64-phase Q23 windowed-sinc reconstruction. For phase `p=0..63` and tap
`j=0..15`, integrate
`sinc(x) * I0(8*sqrt(1-(x/7.5)^2))/I0(8)` over the intersection of
`[j-7-p/64-0.5, j-7-p/64+0.5]` and `[-7.5,7.5]`. Composite Simpson
integration at 128, 256 and 512 subdivisions gives the same rounded values;
each cell is rounded to Q23 and tap 7 or 8 is corrected so the row sums to
8,388,608. The event phase selects and interpolates adjacent rows using the
sample fraction modulo 13,125, with signed nearest/ties-away-from-zero
rounding. This is the pinned core's published reconstruction specification,
not a captured PCM sequence ([audio derivation at the exact source pin](https://github.com/szTheory/muhtari/blob/d5fd241e3f4d701d73867cc2e465c56a6fe6793d/docs/hardware/audio.md)).

Each TIA B-edge level change contributes its signed delta times those
phase-interpolated coefficients. The sample phase advances by 88 modulo
13,125 per master tick; the impulse response is integrated, scaled by 128,
then passed through the fixed Q30 DC blocker
`y = x - x_previous + R*y_previous` with `R=1,070,934,451`. Feedback division
truncates toward zero; final signed-int16 conversion rounds nearest with ties
away from zero. The first interval uses the zero-start handoff state and the
event sequence derived from the published TIA A/B recurrence
([TIA derivation](https://github.com/szTheory/muhtari/blob/d5fd241e3f4d701d73867cc2e465c56a6fe6793d/docs/hardware/tia.md)); the handoff, first interval and carry rules are documented in the
[embedding contract](https://github.com/szTheory/muhtari/blob/d5fd241e3f4d701d73867cc2e465c56a6fe6793d/docs/embedding.md#the-first-frame-after-load).
The expected digest hashes the complete PCM call encoded explicitly as
little-endian signed 16-bit samples. The expected values were generated from
the timing, TIA recurrence, mix curve, kernel integration and blocker
arithmetic before comparing runtime output; the installed consumer only
calculates a digest of actual PCM and compares it with these literals.

For call 1, the sample accumulator starts at zero and runs 8,190 ticks:
`floor(8190 × 88 / 13125) = 54`. For each later call `k` (1-based after the
startup call), the expected count is
`floor((8190+k×119402)×88/13125) - floor((8190+(k-1)×119402)×88/13125)`.
This yields all 15 call counts below. Counts and PCM expectations validate
the consumer boundary; they do not synthesize or report native core ticks.
The adapter exposes no tick getter, so `core_ticks_valid=0` and the tick
count remains zero.

## Recorded generator identity and scope

The relocated consumer generated 16,512 bytes using the project C17
generator compiled by Apple clang 21.0.0 (`clang-2100.1.1.101`). After adding
direction reads, its measured SHA-256 is
`783bcf1c6dd15433451c4d05f03bf8b7cd4d1923fb24cc50ee80548a5a904256`.
The exact core source pin is
`https://github.com/szTheory/muhtari.git` at
`d5fd241e3f4d701d73867cc2e465c56a6fe6793d`.

The executed route built the installed consumer after moving its prefix to an
isolated staging directory. It checked the colocated Muhtari config, archive,
header, license and notices; compiled both an ordinary unsanitized link check
and an ASan/UBSan public consumer; then ran the independent consumer with the
original checkout and build paths unavailable. Exact package and executable
hashes are recorded in the ignored relocation report. This is local evidence
for the stated source, fixture and toolchain; it is not a hosted CI, hardware,
cross-platform, authenticity or reproducibility claim.
