# Generated Nesturbator battery fixture

The public consumer builds this MMC1 battery-backed cartridge from source in
[`tests/nesturbator_save_fixture.h`](../tests/nesturbator_save_fixture.h). It
contains no downloaded image or upstream fixture helper. The content identity
is the SHA-256 of the complete generated cartridge, kept separate from the
`nesturbator-default` configuration identity and the
`nesturbator-save-ram-v1` media identity.

## Generator inputs

| Input | Value |
|---|---|
| Image format | iNES 1 |
| Mapper | 1 (MMC1), submapper 0 |
| PRG | Two 16 KiB banks; initialized to `0xEA` |
| CHR | One 8 KiB ROM bank initialized to zero |
| Header flags | `flags6 = 0x12` (mapper 1 and battery), `flags7 = 0` |
| Program | Original 6502 loop at `$8000`: wait for vblank, increment `$6000`, and repeat |
| Vectors | NMI, reset, and IRQ point to `$8000` in the final PRG bank |
| Generated size | 40,976 bytes |

The source guest changes one byte of its 8 KiB battery span per frame. The
independent literals in
[`tests/nesturbator_save_oracle.h`](../tests/nesturbator_save_oracle.h)
expect `[0x03, 0x00, ...]` after three guest writes and
`[0x04, 0x00, ...]` after one restored frame. The oracle is not calculated from
the generator output.

## Identity and reproduction

The expected cartridge SHA-256 is
`2282919ee95a168d9f37e972bce7858758eccc724bb3e40279b01735244673a9`.
The canonical consumer independently hashes the generated bytes and compares
them with this literal before loading. The host save envelope uses the matching
`sha256:` content identity and stores the effective configuration separately.

## Battery snapshot and save recovery journey

The existing same-process battery recovery route uses release `v0.1.12`, source commit
`2338608ab184f040620a30d17756f5e06a42d4e3`, profile
`nesturbator-ntsc-v1`, and effective configuration `nesturbator-default`.
It runs through the source consumer and a separately relocated installed
consumer on local macOS arm64. It does not qualify other battery layouts or
expand the ordinary same-instance, same-successful-load-session snapshot
boundary.

The program waits for vblank and increments the first battery byte once for
each completed work unit; the remaining bytes stay zero. The consumer advances
twice and captures `[0x02, 0x00, ...]`, then advances once and commits the newer
`[0x03, 0x00, ...]` payload to its selected save path. Restoring the snapshot
returns media to `0x02` while preserving the host's selected newer bytes and
acknowledgment. Because those restored bytes differ, this profile's guest
generation increases by one; a repeated restore of the same bytes leaves it
unchanged. A partial staging-write failure before rename must leave the selected
newer save and acknowledgment byte-for-byte intact. A later successful commit
selects the restored `0x02` payload at the same path, reopens it, and verifies
the exact envelope and all 8192 bytes before advancing the acknowledgment. The
distinct payload is the new durable revision; the fixture uses no revision IDs
or history store.

### Fresh-process battery-backed A/B qualification

Phase 14 separately qualifies this exact battery-backed route through both a
source public consumer and an independently relocated installed public
consumer on local macOS arm64. It uses only the `v0.1.12` /
`2338608ab184f040620a30d17756f5e06a42d4e3` Nesturbator pin, profile
`nesturbator-ntsc-v1`, effective configuration `nesturbator-default`, options
`nesturbator-options-none-v1`, and the complete generated MMC1 image above
(40,976 bytes; SHA-256
`2282919ee95a168d9f37e972bce7858758eccc724bb3e40279b01735244673a9`). The
stable checkpoint identity also binds the LFSNAP2 envelope, LibFuturo and core
build IDs, API/behavior revisions, and native state format. The successful-
load epoch remains instance-local and is not compared between A and B.

Process A loads the exact fixture with R2 in guest battery media and captures
checkpoint S2. It then advances and commits the newer selected host save R3,
writes and successfully closes S2, and exits normally. The supervisor requires
A's close and zero exit before it starts Process B. B loads the matching
fixture, verifies and imports R3 before positive guest work, then restores S2
to R2. B's changed
restore increments its own generation once; repeating an identical restore
does not increment it. Each malformed, truncated, corrupt, and mismatched
checkpoint refusal preserves B's continuation, full media span, B-local
generation, selected R3 bytes, and host acknowledgment.

The R3 host file and acknowledgment stay unchanged through the S2 restore and
a controlled partial staging-write failure before rename. The host explicitly
commits R2 only after that commit succeeds, reopens the selected file, and
verifies its identity, header, exact extent, and complete 8 KiB payload before
advancing the acknowledgment. A separate literal replay work unit after
restore produces three cumulative frames, 2,144,280 cumulative NES half-master
ticks, RGB `0x5A5A5A`, 799 silent mono signed-16 samples, and guest battery
bytes `[0x03, 0x00, ...]`. Those replay literals are independent of the
restore path; the R2 bytes are committed and read back before this later work
returns guest media to R3.

One further guest work unit after restore has independent expected values:
three cumulative frames, 2,144,280 cumulative NES half-master ticks, RGB
`0x5A5A5A`, 799 mono signed-16 audio samples all equal to zero, and the complete
battery span `[0x03, 0x00, ...]`. These literals are maintained in
[`tests/nesturbator_save_oracle.h`](../tests/nesturbator_save_oracle.h), not
derived from the restored run. The authored program's instruction sequence
completes the first three work units at 714,768, 1,429,512, and 2,144,280
ticks. Each work unit targets 714,732 ticks and finishes its active instruction,
accounting for the 36, 12, and 36 tick overruns. With the PPU mask disabled,
the pinned NTSC reset palette supplies the `0x5A5A5A` backdrop; with no APU
channel enabled, audio samples are zero. The audio accumulator carries the
fractional remainder of `714732 * 352 / 315000`, producing 799 samples on the
third unit. The independent source facts and these calculations keep the
oracle from merely comparing two executions of the same restore path.

The original same-process checks remain useful for the earlier journey:

```sh
build/check/nesturbator_session --snapshot-battery
./tests/installed-consumer/relocate-consumer.sh --save-restart
```

The fresh-process battery qualification uses these distinct source and
relocated installed commands from the repository root:

```sh
ctest --test-dir build/check --no-tests=error \
  -R '^nesturbator_battery_fresh_process_snapshot$' --output-on-failure
sh tests/installed-consumer/relocate-consumer.sh \
  --battery-fresh-process-snapshot
```

The canonical `./scripts/check.sh` route also runs contract traceability and
requires separate identity-bound source and installed battery A/B rows. The
Phase 12 identity-bound same-process gate and Phase 13 battery-free fresh-
process gate are historical results; neither substitutes for these Phase 14
routes.

Reproduce the image and verify its digest on macOS from the repository root:

```sh
cmake --build build/check --target nesturbator_session
fixture_path="$(mktemp /private/tmp/libfuturo-mmc1.XXXXXX)"
build/check/nesturbator_session --emit-save-fixture "$fixture_path"
shasum -a 256 "$fixture_path"
rm "$fixture_path"
./scripts/check.sh
```

The generated cartridge is temporary test output. Keep it and all generated
save bytes out of version control.
